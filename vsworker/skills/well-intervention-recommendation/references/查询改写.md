# 多轮对话的检索语句改写

## 为什么必须改写（2026-09-09 实测数据）

| 用户原话 | 直接拿去检索 | 改写后 |
|---|---|---|
| 那泡多久 | **0.6090**，低于阈值 → 没答案 | 「卡钻浸泡解卡剂要泡多长时间」→ **0.8668** 命中 |
| 损失了多少工时 | **0.6480**，而且首位是 **Fana-1**（跟上文那口井无关） | 「Koulele CE-19 2021年10月卡钻损失了多少工时」→ **0.8638**，命中的正是那口井 |

第二行是最危险的情况：不改写不只是查不到，而是**查到别的井头上去**。

## 为什么必须改写

问答对这一级是**纯向量相似度**，比的是一整句话。用户第二轮的话通常省略主语宾语
（「那泡多久？」「损失了多少？」），原样拿去检索，相似度会落到毫无关系的条目上，
或者整体低于阈值白白掉到兜底级。**知识库/图谱那一级同样是单句检索，没有会话记忆。**

所以：**每一轮都要先把用户这句话补成一个能独立看懂的问题，再去检索。**
`scripts/recommend.py` 不做改写，传什么就查什么。

## 七条规则

1. **补全三件事**：事故/事件类型、井号或队号、时间（年月）。上文里有就补，没有就不补。
2. **只补上文明确出现过的信息**。不要替用户猜井深、密度、工序——台账讲究「缺失就写未记录」，
   检索语句里凭空加参数会把相似度带偏。
3. **井名带不带，决定命中哪一层**：
   - 用户问「这口井当时怎么处理的」→ **带井名**（命中单案例条目）。
   - 用户问「这类事故一般怎么办」→ **不要带井名**（命中综合结论聚合条目）。
     带了井名会被 148 条单案例抢命中。
4. **HSE / 井场建设没有井号**，单案例主问题是「队号 + 年月」开头（例 `GW216 2009年11月交通事故`）。
   同一队有多起同名事故（GW216/GW227/GW48 各有两起手指受伤），**必须带年月**才不会撞。
5. **换了事故类型就当新问题**，把上一轮的井号和类型全部丢掉，别继承。
6. **一次只查一个事故类型**。用户一句话里问了两件事，拆成两次 `recommend.py` 调用。
7. **口语词保留 + 补规范词**，不要替换掉用户的原话。
   例：「油管提不动」→ 「油管悬挂器粘连、提不动怎么处理」。

## 知识库那一级要把问题压成术语（2026-09-09 实测）

问答对和知识库对问句形态的偏好**相反**：问答对喜欢完整口语句（库里存的就是一条条问法），
知识库（《钻井事故与复杂问题》的切片）对长句、对比句极不友好 —— 同一个意思换个说法，分值能从 0 跳到 0.99：

| 检索句 | 知识库最高分 |
|---|---|
| 司钻法和工程师法压井有什么区别 | **0 条**（全都低于 0.6 阈值） |
| 司钻法压井 | 0.9067 |
| 压井方法 | 0.9902 |
| 一次循环法压井步骤 | 0.9731 |

所以看到 `decision=no_answer` 且 `kb=empty`、而问题本身又长又像对比题时，
**别直接下结论说《钻井事故与复杂问题》里没有**，把问题压成术语再查一次：

```bash
python3 scripts/recommend.py -q "压井方法" --source kb
```

压法：去掉「有什么区别」「怎么办」「是不是」这类问式外壳，留**术语 + 动作**
（「司钻法和工程师法压井有什么区别」→「压井方法」；「泡解卡剂要泡多久合适呢」→「浸泡解卡剂」）。
一次不行就换个术语，**别去调 `KB_THRESHOLD`** —— 离题片段也有 0.12–0.25，压低阈值等于放垃圾进来。

## 什么时候**不要**重新检索

追问是在问**上一条答案里已有的内容**（「为什么不先震击」「泡多长时间」「损失了多少工时」），
先在上一轮拿到的答案正文里找。找到了就直接答，**不要再检索**——
重复检索只会拿回同一条答案，白花一次往返。
只有答案里确实没有时，才按上面的规则改写并再查一次。

## 改写示例

| 轮次 | 用户原话 | 拿去检索的句子 | 说明 |
|---|---|---|---|
| 1 | 卡钻怎么处理 | `卡钻怎么处理` | 本来就自洽 |
| 2 | 那要泡多久 | （先看上一条答案里有没有浸泡时间；没有才查）`卡钻浸泡解卡剂要泡多长时间` | 补主语 |
| 3 | Koulele CE-19 那次呢 | `Koulele CE-19 2021年10月卡钻是怎么处理的？` | 带井名 → 单案例 |
| 4 | 损失了多少工时 | （先看上一条答案的【损失工时】）`Koulele CE-19 2021年10月卡钻损失了多少工时` | 继承井名与类型 |
| 5 | 井漏呢 | `井漏怎么处理` | 换类型：丢掉井名，不带 Koulele |
| 6 | GW216 那次手指受伤 | `GW216 2023年6月手指受伤是怎么处理的？` | HSE 必须带年月 |
| 7 | 先震击还是先泡解卡剂 | `卡钻该先震击还是先泡解卡剂？` | 冲突检验，必须走问答对 |

## 改写后的一句交代

改写幅度较大时（补了井号、年月、事故类型），在回答开头用一行告诉用户实际查的是什么，例如：

> 按「Koulele CE-19 2021年10月卡钻」检索历史记录：

这样用户能立刻发现补错了对象，而不是读完一段错答案才发现。
