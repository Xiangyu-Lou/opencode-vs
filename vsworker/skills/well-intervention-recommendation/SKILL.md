# 井下作业措施推荐

用户描述一个井下事故或复杂情况，本 skill 给出处理措施。

**一条硬规则贯穿全文：历史处置记录优先于《钻井事故与复杂问题》。** 尼日尔项目 2008–2026 的 148 条真实处置记录
放在平台的问答对里；《钻井事故与复杂问题》（蒋希文, 2006）放在图谱/知识库里。
**两者冲突时以历史记录为准，不得用《钻井事故与复杂问题》"纠正"历史做法。**
（实例：《钻井事故与复杂问题》给的卡钻顺序是 强力活动 → 震击 → 解卡剂；尼日尔 9 起卡钻的实测是震击单独使用 0/4 有效、
浸泡解卡剂 2/2 有效。问「先震击还是先泡解卡剂」必须答解卡剂。）

**当前流程：问答对 → 图谱**，命中即退出。
兜底级那一格是**知识库或图谱、二选一**（`env.json` 的 `KB_ENABLED` / `GRAPH_ENABLED`，
两个都开脚本直接报配置错误，也可以都关）—— 现在放的是图谱。
两者装的都是同一本《钻井事故与复杂问题》，只是切法不同：知识库返回**原文片段**，图谱返回**生成的答案**。
2026-09-10 用 20 条题实测选的图谱：15 条技术题图谱 15 ✓、知识库只有 3 ✓，
且知识库有 4 条**高分假命中**（问「起钻抽吸怎么预防」返回「泥包的预防」，0.7798）。
代价是慢：图谱平均 27 秒、知识库 0.6 秒。对比见仓库 `docs/兜底级对比.md`。

**每个回答都必须说清依据来自哪一层**：尼日尔历史记录（问答对），还是《钻井事故与复杂问题》（知识库/图谱）。
知识库里的《钻井事故与复杂问题》含书上的「例X」现场实例（别的项目的井）

当前部署的三件事，看输出时要知道：
- **五个类别在同一个问答库里**，所以「聚合条目 / 单案例」是按答案正文判的
  （`【结论】` 开头 = 聚合，`【井号】`／`【队号】` 开头 = 单案例），输出里直接标出来。
- **兜底级现在是图谱**（`env.json` 里 `GRAPH_ENABLED=1`、`KB_ENABLED=0`；两个开关都写出来，不能同时为 1）。
  图谱库和知识库装的都是《钻井事故与复杂问题》，台账已经从两个库里移除，
  所以**兜底级命中一律来自《钻井事故与复杂问题》，【依据】就写这五个字的书名**
  —— 不写「图谱」「知识库」，也不补「台账里没有同类记录」。
  图谱一条要 20～48 秒（知识库是 0.6 秒），这是正常的，别当成卡死。
- **图谱答不上来时会用一段通顺的中文硬凑**（先说「描述较少 / 无法直接回答」，
  再拿邻近话题充数）。`is_graph_refusal()` 已按措辞把这类判成落空 → `no_answer`，
  所以**看到 `decision=no_answer` 就照实说没有，不要自己去把图谱那段话捞回来用**。
- **定义题会被挡在问答对之外**：「什么是X」「X是什么意思」这类问题，阈值临时提到
  `QA_DEFINITION_THRESHOLD`（0.90）—— 台账记录的是事故处置，不记术语定义，定义应由《钻井事故与复杂问题》回答。
  输出里会打一行 `[提问类型] 定义题`。看到它就知道为什么没走问答对。

## 工作流程

### 第 1 步：把用户这句话改写成能独立看懂的检索句

**多轮对话里这一步是必做的，不是可选的。** 检索是纯向量相似度比整句话，
用户第二轮的「那泡多久？」缺主语，原样检索必然跑偏。

- 补全：事故/事件类型、井号或队号、年月 —— **只补上文明确出现过的**，不要猜参数。
- 用户问「这类事故一般怎么办」→ **不要带井名**；问「这口井那次」→ **带井名**。
- 换了事故类型就当新问题，丢掉上一轮的井号。
- 追问的是上一条答案里**已经写着**的内容（为什么不先震击、损失多少工时）→ 直接看上一条答案，**不要重新检索**。

规则全文与 7 个改写示例：`references/查询改写.md`。改写幅度大时，回答开头用一行交代实际检索的是什么。

### 第 2 步：跑检索（只有这一条命令）

```bash
python3 scripts/recommend.py -q "改写后的自洽问题"
```

脚本内部就是「问答对 → 未命中才兜底级」，**命中即退出**，不需要你分两次调。

可选参数：`--threshold 0.72`（临时改问答对阈值）、`--k 10`（多召回几条）、
`--kb-threshold 0.5`（临时改知识库阈值）、`--json`（要结构化结果时）。

**用户点名要查某一层时，用 `--source` 跳过默认顺序：**

| 用户说 | 命令 |
|---|---|
| 「书上怎么说」「教材是怎么写的」「查《钻井事故与复杂问题》」「不要历史记录，看通用做法」 | `--source kb` |
| 「查图谱」「按知识图谱回答」 | `--source graph` |
| 「只看我们自己的记录」「不要书上的」 | `--source qa` |
| 没提来源（绝大多数情况） | 不加，走默认的 `auto` |

`--source kb/graph` 会**跳过问答对**，等于放弃「历史优先」，所以**只在用户明确要求时用**，
不要因为自己觉得台账里可能没有就先跳过 —— 那是 `auto` 该做的判断。
指定的库在 `env.json` 里是关着的（比如现在的图谱）也照查，输出会打一行 `[提示]` 说明结果可能不可靠。

### 第 3 步：读输出第一行的 `[决策]`，照表动作

| `[RESULT] decision=` | 含义 | 你要做的事 |
|---|---|---|
| `use_qa_answer` | 问答对命中 | **把「答案正文」原样输出**给用户。不要改写、不要压缩、不要再补《钻井事故与复杂问题》的内容、不要加追问示例。答案是按交付措辞写好的。 |
| `use_kb_answer` | 问答对未命中，知识库有片段 | 片段是**《钻井事故与复杂问题》的原文，不是写好的答案**：按下面的「统一回答结构」自己归纳成结论 + 步骤，**必须写明**「依据来自《钻井事故与复杂问题》」。不要把片段整段倒给用户。 |
| `use_graph_answer` | 问答对未命中，图谱有答案 | 照图谱答案回答，但**必须写明**「依据来自《钻井事故与复杂问题》」。 |
| `no_answer` | 没有可用答案（两级都没命中，或兜底级被关着） | **不要编造措施。** 说明历史台账里没有同类记录（兜底级关着就说明那一级暂时不可用），请用户补充井号/井深/工况，或转人工。**但 `kb=empty` 且问题是长句/对比句时先重试一次**：把问题压成术语再查，见下。 |
| `route_to_well_control` | 命中井控红线（井喷等） | 不做措施推荐。回答：立即执行井控程序（按设计关井、压井）、上报值班、转人工。检索结果只能当背景，不得当作本项目处置经验。 |

用 `--source kb/graph` 跳过问答对时，输出会打 `[跳过问答对]`：这时**必须**告诉用户
「本次只查了《钻井事故与复杂问题》，没查尼日尔历史记录」，并说明默认流程是先查历史记录。

输出里还会出现的提示行：

- `[⚠️ 问答对未发布]` —— 召回到了但 `answer` 是 null：平台上该类别没点「发布」。
  **告诉用户去发布**，不要假装没看见（参见 `平台部署说明.md` §8.4）。
- `[排序调整]` —— 问题没带井名，已把「综合结论」聚合条目提为首选。正常现象。
- `[同时命中的其他条目]` —— 供你判断用，用户没追问就别拼进答案。

## 统一回答结构（三种来源都用这一套）

不管答案来自问答对、知识库还是图谱，给用户看到的结构应当一致。
**三级检索是内部的事，用户看到的出处只有两种。**

```
【结论】一句话说清现在该做什么（最关键的动作放第一句）
【依据】二选一，照抄，不加别的：
        · 尼日尔历史记录（点名井号与年份）
        · 《钻井事故与复杂问题》（知道章节就带上「第X章第Y节」）
【处置步骤】1. 2. 3.（有先后就按先后写，别只给一堆并列选项）
【注意】禁忌、升级/停止判据、缺失的信息
```

三条硬规则：

1. **问答对命中时原样输出，不要再套模板** —— 它本来就是这个结构（`【结论】`/
   `【尼日尔历史记录统计】`/`【依据记录】`/`【《钻井事故与复杂问题》】`），重排只会弄丢信息。
2. **`【依据】` 只有两个取值**：`尼日尔历史记录` 或 `《钻井事故与复杂问题》`。两件事都不要做 ——
   - **不写检索通道。**「问答对」「知识库」「图谱」「知识图谱生成答案」是内部三级检索的名字，
     只出现在脚本输出的 `[来源]` 行里（`[来源] 图谱库（《钻井事故与复杂问题》）`），**不许进用户看到的答案**。
     用户要知道的是「这话是台账里的还是书上的」，不是我们用哪个库查到的。
     ——「《钻井事故与复杂问题》（知识图谱生成答案）」是错的，写「《钻井事故与复杂问题》」。
   - **不写否定句。** 不补「尼日尔历史台账中没有同类记录」「是通用做法、非本项目实践」。
     出处写清楚了，读的人自然知道不是台账。（`no_answer` 是另一回事：那时「没有同类记录」本身就是答案。）

   片段里出现的井名、井深、事故经过是**书上别的项目的案例**，可以引用，但要说清那是《钻井事故与复杂问题》里的例子。
3. 不编数字：井号、井深、工时、参数缺失就写「未记录」，不要从《钻井事故与复杂问题》的片段里挪一个数字过来充数。

这是**措辞引导，不是格式校验**：某一节实在没内容就省掉，不要为了凑格式硬写。

## 回答措辞（问答对答案正文已经按这套写好，你别破坏它）

- 说「**尼日尔历史记录中**」，不说「本项目」。
- 引用历史做法时点名**哪口井、哪一年**。
- 来自书里的内容**必须显式写明**「依据来自《钻井事故与复杂问题》」。
- **【依据】只有两种出处**：`尼日尔历史记录` / `《钻井事故与复杂问题》`。
  不写「问答对」「知识库」「图谱」这些内部通道名，也不写「不是来自哪里」。
- **不编造**井号、井深、时间、工时、参数 —— 缺失就写「未记录」。
- 末尾不要加追问示例。

## 其他命令（排查和调优时才用）

```bash
# 配置与连通性自检：换环境、换 token、报鉴权错时先跑这个。看最后一行 [自检结果]
python3 scripts/check_env.py

# 只跑第一级，看召回明细（含阈值以下的）
python3 scripts/qa_search.py -q "卡钻怎么处理？" --k 10 --show-all

# 只跑兜底级：知识库片段（--full 看全文，默认每段截到 600 字）
python3 scripts/kb_search.py -q "键槽卡钻怎么判断" --full

# 只跑兜底级：图谱实体与关系（GRAPH_ENABLED=1 时才有意义）
python3 scripts/graph_search.py -q "什么是键槽卡钻" --graph

# 标定阈值：用 31 条正/负例扫一遍，最后一行给建议值，填回 env.json 的 QA_THRESHOLD
python3 scripts/tune_threshold.py --cases assets/threshold-cases.txt --out /workspace/tune.json

# 导入核对：从 dist 的问答对文件抽问法回查，确认整批真的进了向量库（每次重新导入后跑）
python3 scripts/verify_import.py --sample 60          # --sample 0 = 全查，1353 条约 3.5 分钟
```

**所有配置都在 skill 根目录的 `env.json`**（平台注册 skill 时会自动解析它、把键值写进环境变量；
本地跑脚本自己读同一份）。`_` 开头的键是注释。临时改一个值用同名环境变量覆盖，
例如 `KB_ENABLED=0 python3 scripts/recommend.py -q "…"`；换一整份配置用 `WIR_ENV_FILE=/path/to/x.json`。

脚本路径写**相对**（相对 skill 根），产物路径写**绝对**（`/workspace/...`）；不要 `cd` 到 skill 目录。
若运行时的 cwd 不是 skill 根（例如在 Claude Code 里从仓库根执行），把命令前缀换成
`python3 skills/well-intervention-recommendation/scripts/...`，其余参数不变。

## 故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `[配置错误] PLATFORM_BASE_URL 没填` 等 | `env.json` 缺键或写错 | 补上那个键（所有变量都在 skill 根目录的 `env.json`），再跑 `check_env.py` |
| 任何一级报 `status=610` / `611` | **多半是路由拼错，不是鉴权**。网关对不存在的路由一律回 610「No authentication information .」，带上格式合法的 `Authorization` 就变 611 —— 极像 token 过期。三级当前都不需要任何鉴权头 | 先核对 `platform_client.py` 顶部三个路径常量（图谱是 `/backend/lightrag/search`，**不带 `-py`**；问答对和知识库那两个才带）。路由没错，才考虑平台改回要鉴权，把 `PLATFORM_TOKEN` + `PLATFORM_EXTRA_HEADERS` 填进 `env.json` |
| 连不上平台 | 不在内网 | 确认 VPN，再核对 `PLATFORM_BASE_URL` |
| 请求返回 502 / 超时，但浏览器能打开平台 | 本机代理（Clash 等）把内网地址劫走了 | 脚本默认已绕开系统代理；若被人改成 `PLATFORM_USE_PROXY=1`，设回 `0` |
| 召回到了但 `answer` 为 null | 问答对没发布 | 平台上五个类别逐个点「发布」，「未发布: N」归零 |
| 图谱没收到 `[DONE]` | 超时或连接断 | 调大 `env.json` 的 `GRAPH_TIMEOUT`，重试一次 |
| `[图谱错误] HTTP 404` | 路由不对。图谱是 `/backend/lightrag/search`，**不带 `-py`** | 核对 `platform_client.py` 顶部的 `GRAPH_PATH`。历史上写成 `lightrag-py` 时不是 404 而是 610，见上一行 |
| 该命中的问题落到了兜底级 | 问答对阈值偏高 | 跑 `tune_threshold.py` 重新标定 |
| `[配置错误] KB_ENABLED 和 GRAPH_ENABLED 只能开一个` | 兜底级是二选一 | `env.json` 里把其中一个设为 0（图谱入库期间留知识库） |
| `[知识库] 零片段`，但问题明显是《钻井事故与复杂问题》该答的 | 知识库对长句/对比句极不友好（「司钻法和工程师法压井有什么区别」0 条，「压井方法」0.9902） | 把问题**压成术语**再查一次：`--source kb -q "压井方法"`。规则见 `references/查询改写.md` |
| `[知识库] 零片段`，问题本身就离题 | 库里确实没有 | 如实答「没有同类记录」。**别调低 `KB_THRESHOLD`**：离题片段分值也有 0.12–0.25，压低等于放垃圾进来 |
| 明明台账里有，却答了《钻井事故与复杂问题》 | 自己加了 `--source kb/graph` | 那两个只在用户点名要查《钻井事故与复杂问题》时用；默认永远是 `auto`（先查历史记录） |
| 定义题被答成了措施推荐 | 定义题规则没拦住 | 看 `platform_client.is_definition()` 的匹配模式，补一条 |
| 新加的问法检索不到 | 被写进了扩展问列 | 平台只向量化 `name` 列：每个问法必须占**独立一行**（`build_qa.py` 已如此，别改回 1+5 打包） |
| 通用问题被某口井的单案例抢了命中 | 聚合条目扩展问不够 | 确认 `QA_PREFER_AGGREGATE=1`；仍不对就回仓库给聚合条目加扩展问 |

## 不做的事

- 不自己训练、不自己存问答对和《钻井事故与复杂问题》原文——检索全部走平台接口。
- **兜底级只开一个**：知识库和图谱装的都是《钻井事故与复杂问题》，同时开只会让答案来源说不清。
- **井喷不做措施推荐**：历史台账对井喷零覆盖，这里「历史优先」规则是反的，一律转井控程序与人工。
- 不改写问答对返回的答案正文。
